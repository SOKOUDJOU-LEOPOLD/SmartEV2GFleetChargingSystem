# Coding Rules

> **Everyone — human or AI agent — reads this file before touching the project.**
> Then read [`docs/plan/ROADMAP.md`](docs/plan/ROADMAP.md) to see where we are.

## 1. Before you start
1. Read this file and the [roadmap](docs/plan/ROADMAP.md).
2. Find the phase file for the task (`docs/plan/phase-*.md`) and check its task list and status.
3. Pull the latest `main` and create a branch (rule 2).
4. When you finish a task, tick its checkbox in the phase file **in the same PR**.

## 2. Git workflow
- **Branch name:** `<firstname>/<type>/<phase>-<short-name>` — lowercase, words separated by hyphens.
  - `<firstname>`: who owns the work (`leopold`, `yeshas`, …). **An AI agent uses the first name of the person who launched it**, and asks if unsure.
  - `<type>`: `feat` (new code) · `fix` (bug fix) · `exp` (running experiments) · `docs` (documentation) · `chore` (setup/tooling) · `refactor` (restructure, same behaviour) · `test` (tests only)
  - `<phase>`: `p0` … `p7` (see roadmap)
  - Examples: `leopold/chore/p0-repo-setup`, `yeshas/feat/p2-departure-wrapper`, `leopold/exp/p4-main-grid`
- **One logical group of tasks per branch.** Always branch from the latest `main`.
- **Publish a new branch immediately:** right after creating it, push it (`git push -u origin <branch>`) and check it is visible on GitHub **before** making any local changes on it. Teammates can then see who is working on what.
- **Never commit directly to `main`.** Changes reach `main` only through a Pull Request with green CI and a review by the other teammate.
- Shared work: the person who opens the PR owns the branch; the other teammate reviews.
- If your branch needs work from another branch, get that PR merged into `main` first, then `git rebase main`.
- Delete the branch after merging.
- **Commit messages:** [Conventional Commits](https://www.conventionalcommits.org/) — `type(scope): short summary`, e.g. `feat(wrapper): sample hidden early departure time`. Small, atomic commits.
- **No AI attribution:** commits and PRs must **not** contain `Co-Authored-By:` lines for AI tools, "Generated with …" lines, or similar signatures.
- AI agents: **ask the user before pushing or opening a PR.**
- Milestone tags on `main`: `v0.1-pipeline`, `v0.2-wrapper`, `v1.0-deliverable1`, `v2.0-stretch`.

## 4. Code style
- Python **3.12**, code lives in `src/smartev2g/` (installable package), entry points in `scripts/`.
- Format and lint with **ruff** (`ruff format .` and `ruff check .`) — pre-commit runs it automatically.
- Type hints on all functions; a short docstring on every public function/class.
- **No magic numbers** in code: every tunable value lives in a YAML file in `configs/`.
- Use the agent names exactly: `PPO-RiskAware` (ours), `PPO-Trusting`, `PPO-Oracle`, `AFAP` (in code/ids: `ppo-riskaware`, `ppo-trusting`, `ppo-oracle`, `afap`).
- Notebooks (`notebooks/`) are only for exploration. Anything used for results must be in `src/` or `scripts/`.

## 5. Reproducibility
- Every run is defined by **a config file + a seed**. No hidden settings.
- Every run saves `run_info.json` (resolved config, seed, git commit, library versions, CPU/GPU model, start/end time, wall-clock) and gets one line in [`docs/experiments/EXPERIMENT_LOG.md`](docs/experiments/EXPERIMENT_LOG.md).
- Run experiments from a **clean, committed** state so the git commit hash identifies the code.
- **Never mix train, validation and test seeds/scenarios.** Test scenarios are fixed and versioned in `configs/`.
- Report results over **≥ 5 seeds** with mean ± 95% CI.

## 6. Metrics logging
- Every training/evaluation script logs to **wandb** (with group + tags) **and** writes the local files listed in [`docs/plan/METRICS_AND_LOGGING.md`](docs/plan/METRICS_AND_LOGGING.md): losses, per-episode metrics, validation, per-EV, trajectories.
- Rule of thumb: **if it might go in the paper, log it.**
- Figures are generated by `scripts/make_figures.py` from saved files only.

## 7. Long-running jobs
- Launch long jobs detached so they survive a closed terminal or a restarted session:
  `setsid nohup python scripts/train.py --config ... --seed ... > results/logs/<run_id>.log 2>&1 &`
- Training must save checkpoints and be **resumable**.
- RL here is mostly CPU work: run many seeds in parallel as separate processes. Use the GPU only where the timing test shows it is faster.

## 8. What never goes into git
- `.venv/`, caches, `results/`, `wandb/`, model checkpoints, TensorBoard logs, downloaded data (`data/`), `.env` and any secret (API keys, tokens).
- Only small summary CSVs and final figures under `reports/` are committed.

## 9. Dependencies
- Runtime deps pinned in `requirements.txt`; dev tools in `requirements-dev.txt`.
- Adding a dependency ⇒ add it (pinned) to the right file **in the same PR**.

## 10. Tests & CI
- Every new module gets unit tests in `tests/`.
- Run `pytest` and `ruff check .` before pushing. CI runs both on every PR; **a PR cannot be merged with red CI.**
- Tests must not need wandb or a GPU (set `logging.wandb: disabled`).

## 11. Documentation
- Big or surprising choices get a short decision record in `docs/decisions/ADR-XXXX-<topic>.md` (template in that folder).
- Keep the phase files' checkboxes and status up to date.
